# Automatic range proposals — Milestones 29–30

## Review workflow

Create and save reference-paced slots first, including duration/order edits. **Suggest an assembly** analyzes retained footage offline and creates a separate proposal. Lock saved assignments to preserve their clip/range. **Allow reused ranges** is off by default. Review each explanation and proposed range in the native source player; **Apply proposal to draft** requires confirmation before replacing unsaved edits. Adjust manually and **Save sequence** explicitly. Incomplete proposals keep unfilled slots and explain how to upload footage, shorten slots, unlock choices or permit reuse. Nothing loops, stretches or silently shortens footage.

Unchanged settings/sources reproduce the same chosen ranges; repeating a completed identical request returns its saved proposal. These are motion/scene/image heuristics, **not subject recognition, highlight understanding or objective artistic quality**. Dark, quiet and soft scenes can be intentional. Milestone 30 adds an explicitly installed local visual-similarity mode, described below. Measurement mode remains available without a model. Existing recipe/audio/caption/font/framing settings are untouched; saving sequence edits uses their existing outdated-output/timeline rebinding rules.

## Actual method and bounds

Candidate algorithm **rgb-motion-2fps-64-v1**, current selection **visual-ranges-v2**, compatible proposal schema 1, additive SQLite schema **19** (M29 was measured-ranges-v1/schema 18). Each source is decoded once at **2 fps**, normalized video PTS, autorotated, area-scaled to an even canvas with maximum edge **64**, preserving display aspect within rounding (no crop/padding). Retain up to 240 sampled RGB frames/source. FFmpeg version and SDR metadata warnings are recorded. Existing SDR policy rejects unsupported/HDR metadata; untagged HDR cannot be identified reliably. [FFmpeg fps/scale documentation](https://ffmpeg.org/ffmpeg-filters.html#fps).

Brightness is mean encoded BT.709-weighted RGB. Motion is mean absolute inter-sample RGB difference / 255; first sample is zero. Sharpness is mean absolute four-neighbor brightness Laplacian / 4. Sample differences >=0.20 mark approximate scene boundaries. This can confuse motion/flashes with cuts and miss changes shorter than 0.5 seconds or similar-looking scenes; it is not the reference's consecutive-frame scdet detector.

Candidate starts are 0.5-second grid points, approximate boundaries, the latest full-length start and occupied-range ends; exact lengths stay on the saved 30 fps grid. For a range: score = -5 × internal sampled boundaries -2 × |reference motion - candidate motion| -0.3 × max(0,0.08-brightness)/0.08 +0.2 × min(1,sharpness/0.03) -0.08 × prior selections from this clip -1 if overlapping under explicit reuse. Measurements average samples inside the range (nearest sample if none). M29 historically mapped output positions proportionally into the reference. M30 replaces this with explicit `reference_start_frame` / `reference_end_frame` provenance: generated intervals stay with the stable slot ID through reorder/resize/apply/save. Legacy clients omitting the fields preserve the existing interval; explicit null clears it. Legacy/manual slots without an association compare whole-reference motion and are visibly labeled as measurement selection. No correspondence is guessed from current order. Deterministic greedy selection in saved slot order, ties by rounded score, stable clip ID then start. Reserve all locked ranges first. Soft image preferences never blanket-reject dark/low-motion clips. Greedy selection is not a globally optimal packing/artistic edit; an unfilled slot may need manual changes even if another arrangement could fit.

Entire job: **120-second monotonic deadline**, at most **11 sources / 2,640 samples**, existing 10-clip/500 MiB aggregate footage and 100 MiB/file (reference 50 MiB), 60 slots/3,600 output frames. One sequential decode at a time, 60-second decode stage capped by remaining time, <=2,949,120 raw bytes/tool, bounded metadata/diagnostics, **8 MiB polled staging budget** (100 ms; possible overshoot, not a filesystem quota). Existing containment and joins/cleanup remain; unconfirmed termination quarantines staging and blocks further media work. Source validation outside the job uses aggregate 10-second hash-check caps. No second worker or queue.

Cache key is project + source SHA-256 + algorithm/settings version, not filename/clip ID. Identical retained bytes can share measurements. Prune incompatible/unreferenced cache entries at start: at most eleven current hash entries. Cached analyses record their original FFmpeg version; upgrade the algorithm version when changing interpretation. Cache reuse still validates source identity/hash before proposal publication/application.

## API / persistence / lifecycle

GET/POST `/api/projects/{id}/assembly` use the existing operation/polling envelope plus completed/total sources and previous proposal. POST settings: `expected_sequence_revision`, `allow_reused_ranges`, `locked_slot_ids`, optional `matching_mode=measurements|subject_aware` (default measurements). Saved proposal binds exact input sequence (including pacing identity), every available source hash, algorithm/settings, choices/explanations/warnings and incomplete slots. An unavailable library item is not a candidate. Missing/changed assigned sources require fixing the saved sequence first.

POST suffix `/apply` includes the same settings plus `proposal_id`; server revalidates bindings and returns assignments for the client draft, **never saves the sequence**. Settings/revisions/hashes changing reject application. POST suffix `/cancel` stops/joins only this project's matching assembly owner. Failure/cancellation keeps the last completed proposal and saved sequence. Current-job UUID, active project, exact sequence and hash checks protect publication; restart marks interrupted work failed without retry. Deletion joins/cleans via the shared worker and cascades proposal/cache rows. Poll requests/project switching cannot apply late responses to another project.

## Saved sequence caption previews

Caption still/motion requests now accept `expected_sequence_revision`. They validate the saved caption timeline and reuse the **same `assemble_sequence` helper as export**, clipped to the requested output interval, with audio disabled and existing **30-second / 16 MiB staging** preview limits. Caption processing follows source assembly/framing/color. Restore absolute output PTS before libass, then rebase only the finished motion preview; entrances do not restart at slot boundaries. Source hashes and settings are rechecked before return. Still result identifies the selected clip/range; motion spec retains all sequence bindings. Existing 960-pixel still edge, 640-pixel motion edge, four-second/120-frame/four-MiB motion bounds and explicit outdated feedback remain.

## Subject-aware visual matching — Milestone 30

### Explicit setup and model identity

Run in `backend`:

```powershell
uv sync --locked --extra visual
uv run --locked --extra visual python visual_matching.py setup
uv run --locked --extra visual python visual_matching.py ready
```

Include `--extra transcription` as well when retaining automatic-caption dependencies. Setup is the only network path. No model download/load occurs at startup, project opening or readiness checks. Weights live in ignored `data/visual-models/<revision>/vision.onnx`. Readiness checks file size and exact installed dependency versions; analysis also verifies the weight SHA-256 before use. GET `/api/visual-model` supplies readiness/setup guidance. Missing/corrupt assets or inference failure never silently switch matching modes or replace the previous proposal.

[CLIP ViT-B/32](https://github.com/openai/CLIP), [Xenova ONNX conversion](https://huggingface.co/Xenova/clip-vit-base-patch32/tree/d15189d7028b43f1d3e65039190477f6af591c2a/onnx), quantized **image encoder only**. Exact revision **d15189d7028b43f1d3e65039190477f6af591c2a**, SHA-256 **583fd1110a514667812fee7d684952aaf82a99b959760c8d7dca7e0ab9839299**, **89,117,001 bytes (85 MiB)** download/storage plus optional dependencies. CLIP's upstream repository is [MIT licensed](https://github.com/openai/CLIP/blob/main/LICENSE); the converted-weight repository points to the upstream model and supplies no separate license. The upstream [model card](https://huggingface.co/openai/clip-vit-base-patch32) cautions against untested deployment; this is experimental local, user-reviewed matching, not deployment validation. No remote Python/custom model code, pickle, text encoder, object classifier or invented labels.

Pinned optional dependencies: **ONNX Runtime 1.30.0**, NumPy 2.5.3, Pillow 12.3.0, psutil 7.2.2. [CPUExecutionProvider](https://onnxruntime.ai/docs/api/python/api_summary.html), two intra-op threads/one inter-op thread, batch size one. Source orientation and pixel aspect ratio use existing framing geometry. FFmpeg bicubic resizes the display image until its short edge reaches 224, then center-crops 224 × 224 RGB. Normalize encoded pixels /255 by CLIP mean **0.48145466 / 0.4578275 / 0.40821073**, standard deviation **0.26862954 / 0.26130258 / 0.27577711** ([processor specification](https://huggingface.co/Xenova/clip-vit-base-patch32/blob/d15189d7028b43f1d3e65039190477f6af591c2a/preprocessor_config.json)). FFmpeg bicubic is a documented implementation choice rather than bit-identical Pillow preprocessing. Cropping can hide edge subjects. Upgrade `clip-q8-2fps-center224-v1` when changing this interpretation.

### Samples, scoring and bounds

Reuse M29 measurements/cache. For uncached embeddings, decode each unique retained source once at the same normalized **2 fps** timestamps, rather than repeatedly decoding candidate ranges. The separate 64-pixel measurement pass remains when those measurements are uncached. Decodes are sequential; one contained subprocess loads the model once for all uncached sources. Sample first/middle/last grid frames inside each reference interval and candidate range (two or three distinct samples). Fewer than two samples in either interval yields explicitly labeled measurement selection for that slot, not semantic success. Manual/legacy unassociated slots similarly use measurements; regeneration establishes associations with existing replacement confirmation.

Average all reference/candidate sample-pair cosine similarities, then add **4 × cosine** to the documented M29 score. Ties, locks, exact lengths, nonoverlap/reuse, greedy packing and explicit draft application/Save remain unchanged. Weak flag: cosine <0.65. Ambiguous flag: selected cosine minus the highest other eligible clip's cosine <0.05. These are review heuristics, **not calibrated confidence/probability or proof of a subject**; they were fixed before the fixture benchmark. Motion/scene penalties can outweigh similarity. Locked assignments remain unchanged. Saved proposals include matching mode, exact model revision/preprocessing identity, score, sample frame indices and bounded 128-pixel JPEG comparison images. Changing associations, sources, revisions or algorithm versions makes proposals stale. Old proposals/sequences remain readable; existing projects are not analyzed automatically.

Same shared worker, **120-second total monotonic deadline**, cancellation, stale publication checks, restart/deletion joining and quarantine on unconfirmed containment. Semantic bounds: **512 unique project frames / 240 per source**, <=11 hashes, one model/batch-one inference, 8,192-pixel maximum scaled dimension, **24 MiB captured JSON**, **96 MiB aggregate staging**, **32 MiB live visual cache/project**. Cache keys are project/source SHA-256/analysis version; each record also validates exact model revision, sorted grid timestamps, finite unit 512-dimensional vectors and bounded JPEG data. Prune noncurrent hashes/versions at start; deletion cascades rows. Source hashes are revalidated before publication and application.

Inference's own RSS watchdog checks every **100 ms**, exits above **1 GiB**; staging checks also poll every 100 ms. Both can overshoot between checks; neither is a strict allocation/filesystem quota. Parent memory is bounded by raw/captured/cache sample sizes, not an RSS quota. Failed/oversized/malformed output fails explicitly, preserving the previous proposal. The metadata inspector accepts this caller's larger staging budget while ordinary color analysis retains its 2 MiB default.
