# Automatic range proposals — Milestone 29

## Review workflow

Create and save reference-paced slots first, including duration/order edits. **Suggest an assembly** analyzes retained footage offline and creates a separate proposal. Lock saved assignments to preserve their clip/range. **Allow reused ranges** is off by default. Review each explanation and proposed range in the native source player; **Apply proposal to draft** requires confirmation before replacing unsaved edits. Adjust manually and **Save sequence** explicitly. Incomplete proposals keep unfilled slots and explain how to upload footage, shorten slots, unlock choices or permit reuse. Nothing loops, stretches or silently shortens footage.

Unchanged settings/sources reproduce the same chosen ranges; repeating a completed identical request returns its saved proposal. These are motion/scene/image heuristics, **not subject recognition, highlight understanding or objective artistic quality**. Dark, quiet and soft scenes can be intentional. Subject-aware AI matching remains pending; no model/API/download was added. Existing recipe/audio/caption/font/framing settings are untouched; saving sequence edits uses their existing outdated-output/timeline rebinding rules.

## Actual method and bounds

Candidate algorithm **rgb-motion-2fps-64-v1**, selection **measured-ranges-v1**, proposal schema 1, additive SQLite schema **18**. Each source is decoded once at **2 fps**, normalized video PTS, autorotated, area-scaled to an even canvas with maximum edge **64**, preserving display aspect within rounding (no crop/padding). Retain up to 240 sampled RGB frames/source. FFmpeg version and SDR metadata warnings are recorded. Existing SDR policy rejects unsupported/HDR metadata; untagged HDR cannot be identified reliably. [FFmpeg fps/scale documentation](https://ffmpeg.org/ffmpeg-filters.html#fps).

Brightness is mean encoded BT.709-weighted RGB. Motion is mean absolute inter-sample RGB difference / 255; first sample is zero. Sharpness is mean absolute four-neighbor brightness Laplacian / 4. Sample differences >=0.20 mark approximate scene boundaries. This can confuse motion/flashes with cuts and miss changes shorter than 0.5 seconds or similar-looking scenes; it is not the reference's consecutive-frame scdet detector.

Candidate starts are 0.5-second grid points, approximate boundaries, the latest full-length start and occupied-range ends; exact lengths stay on the saved 30 fps grid. For a range: score = -5 × internal sampled boundaries -2 × |reference motion - candidate motion| -0.3 × max(0,0.08-brightness)/0.08 +0.2 × min(1,sharpness/0.03) -0.08 × prior selections from this clip -1 if overlapping under explicit reuse. Measurements average samples inside the range (nearest sample if none). Reference correspondence uses saved output positions proportionally mapped into retained reference duration, so order/duration edits change the compared window; this is timing correspondence, not semantic shot matching. Deterministic greedy selection in saved slot order, ties by rounded score, stable clip ID then start. Reserve all locked ranges first. Soft image preferences never blanket-reject dark/low-motion clips. Greedy selection is not a globally optimal packing/artistic edit; an unfilled slot may need manual changes even if another arrangement could fit.

Entire job: **120-second monotonic deadline**, at most **11 sources / 2,640 samples**, existing 10-clip/500 MiB aggregate footage and 100 MiB/file (reference 50 MiB), 60 slots/3,600 output frames. One sequential decode at a time, 60-second decode stage capped by remaining time, <=2,949,120 raw bytes/tool, bounded metadata/diagnostics, **8 MiB polled staging budget** (100 ms; possible overshoot, not a filesystem quota). Existing containment and joins/cleanup remain; unconfirmed termination quarantines staging and blocks further media work. Source validation outside the job uses aggregate 10-second hash-check caps. No second worker or queue.

Cache key is project + source SHA-256 + algorithm/settings version, not filename/clip ID. Identical retained bytes can share measurements. Prune incompatible/unreferenced cache entries at start: at most eleven current hash entries. Cached analyses record their original FFmpeg version; upgrade the algorithm version when changing interpretation. Cache reuse still validates source identity/hash before proposal publication/application.

## API / persistence / lifecycle

GET/POST `/api/projects/{id}/assembly` use the existing operation/polling envelope plus completed/total sources and previous proposal. POST settings: `expected_sequence_revision`, `allow_reused_ranges`, `locked_slot_ids`. Saved proposal binds exact input sequence (including pacing identity), every available source hash, algorithm/settings, choices/explanations/warnings and incomplete slots. An unavailable library item is not a candidate. Missing/changed assigned sources require fixing the saved sequence first.

POST suffix `/apply` includes the same settings plus `proposal_id`; server revalidates bindings and returns assignments for the client draft, **never saves the sequence**. Settings/revisions/hashes changing reject application. POST suffix `/cancel` stops/joins only this project's matching assembly owner. Failure/cancellation keeps the last completed proposal and saved sequence. Current-job UUID, active project, exact sequence and hash checks protect publication; restart marks interrupted work failed without retry. Deletion joins/cleans via the shared worker and cascades proposal/cache rows. Poll requests/project switching cannot apply late responses to another project.

## Saved sequence caption previews

Caption still/motion requests now accept `expected_sequence_revision`. They validate the saved caption timeline and reuse the **same `assemble_sequence` helper as export**, clipped to the requested output interval, with audio disabled and existing **30-second / 16 MiB staging** preview limits. Caption processing follows source assembly/framing/color. Restore absolute output PTS before libass, then rebase only the finished motion preview; entrances do not restart at slot boundaries. Source hashes and settings are rechecked before return. Still result identifies the selected clip/range; motion spec retains all sequence bindings. Existing 960-pixel still edge, 640-pixel motion edge, four-second/120-frame/four-MiB motion bounds and explicit outdated feedback remain.
